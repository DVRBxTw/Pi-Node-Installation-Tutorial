CHAPTER 02

Windows 安裝流程

以下按順序完成 Windows 環境、Pi Desktop 登入與 Node 初始化；Port 設定及故障排除列於後續章節。

1

下載並安裝 Pi Desktop

只從 Pi Network 官方網站取得安裝檔。安裝完成後開啟 Pi Desktop，依畫面登入，先完成下方 WSL／Docker 準備，再到 Node 頁面設定。

Pi Node 官方下載頁 ↗Docker 官方下載 ↗
2

準備 WSL／Docker，再初始化 Node

依下方詳細步驟啟用虛擬化、安裝／更新 WSL，並啟動 Docker Desktop。確認 Docker 引擎可用後，回 Pi Desktop 的 Node 頁面完成環境檢查；已有節點請先查看升級提示，不要套用舊版設定檔。

3

啟動 Node 並觀察同步

完成初始化後，依 Pi Desktop 的提示開啟 Node。Docker 容器及狀態以目前 App 與 Docker 顯示為準。

✓ 確認 Pi Desktop 顯示 Node 已啟動，Docker 正常運作，並觀察同步狀態是否更新。
4

按 App 提示設定 Port

Pi Node 0.6.2 起支援相容路由器的 UPnP 自動設定。若 App 顯示仍需手動設定，再依後面的路由器與防火牆章節操作。

WINDOWS 安裝與首次登入補充

從電腦準備到進入 Node 頁面

以下補上 Windows 與首次登入細節。配圖包含本機畫面及社群參考安裝教學 ↗；部分是 Windows 10 與舊版 Pi Desktop 畫面，只作位置示意。介面可能更新，請以目前 Pi Desktop 與官方安裝提示為準。

1

先確認 CPU 虛擬化已啟用

在工作管理員「效能 → CPU」查看「虛擬化」。若未啟用，依電腦／主機板原廠說明，在 BIOS/UEFI 開啟 Intel VT-x 或 AMD-V（有些介面稱 SVM）。需要查主機板型號時，在 Windows PowerShell 執行：

查詢主機板廠牌與型號（PowerShell）Get-CimInstance -ClassName Win32_BaseBoard | Select-Object Manufacturer, Product

也可按 Win + R，輸入 msinfo32 開啟系統資訊。WMIC 已淘汰；本頁改用 PowerShell CIM 指令。Microsoft WMIC 說明 ↗

2

安裝／更新 WSL，確認版本

以下指令在 Windows PowerShell 執行。先用 wsl --version 查看版本；已安裝者直接更新即可。Docker 需要 WSL 2.1.5 以上；這裡的版本號與「WSL 1／WSL 2」執行模式是不同概念。

尚未安裝 WSL：以系統管理員身分執行wsl --install --no-distribution

安裝 WSL 與所需功能後，依提示重新啟動。Docker Desktop 不要求另外安裝 Ubuntu；若你也需要 Linux 開發環境，可依 Microsoft 文件另裝發行版。

已安裝 WSL：更新後再次確認版本wsl --update

完成後再次執行 wsl --version；若提示重新啟動，先完成再開 Docker。若指令只顯示說明或不支援此選項，依 Microsoft 安裝文件處理。

新版優先採用上述流程。下圖的手動勾選功能與舊版核心 MSI 屬舊系統替代流程，無須全部重做。Microsoft 安裝說明 ↗ · WSL 指令說明 ↗

3

啟動 Docker Desktop，確認 Linux 容器引擎

依官方安裝程式選擇 WSL 2 後端；必要時重新啟動，再從開始功能表開啟 Docker Desktop 並閱讀服務條款。到 Settings → General 確認 WSL 2 引擎（部分版本預設啟用，不顯示選項）。若目前是 Windows containers 模式，從 Docker 選單切換至 Linux containers。

確認 Docker 用戶端與引擎可連線docker version

應同時顯示 Client 與 Server。若只有 Client 或無法連線，先等引擎啟動並查看 Docker 錯誤；在引擎正常之前，不要繼續 Node 初始化。

讓 Docker Desktop 保持執行。WSL 內不需再自行安裝另一套 Docker Engine。Docker WSL 2 官方說明 ↗

4

登入 Pi Desktop 並完成首次申請

在 Pi Desktop 選擇登入，依當前畫面與手機 Pi App 完成帳號連結。登入後進入電腦端 Node 頁面；若帳號仍顯示 APPLY／申請問卷，再依提示填寫。下圖的 LOGIN、SUBMIT、CONTINUE 為舊版介面示例，並非所有版本的必經畫面。登入碼屬登入憑證，請勿分享。

5

確認 Docker 狀態，再啟動 Node

若 Node 頁面的 Docker 狀態未顯示正常，先排除 Docker 問題。依 App 顯示的步驟處理連線設定，再開啟 Node 主開關。Pi Desktop 會依目前流程啟動所需容器；舊版畫面曾使用 pi-consensus 名稱，實際狀態與容器名稱請以目前 App 為準。

6

讓節點持續執行並查看同步進度

先將 Pi Desktop 視窗最小化，保持 Node 與 Docker Desktop 執行。關閉視窗是否繼續背景運作取決於版本／設定，請實際確認系統匣與容器狀態，不要直接選擇結束程式。Windows「設定 → 系統 → 電源」中，依需求避免插電時睡眠；螢幕關閉不等於睡眠。重新登入或開機後，確認 Docker 與 Node 都已恢復，再依下方排錯章節觀察區塊進度。

PORT 測試注意事項

舊版測試方式：參考教學中的「Check now」曾透過 Docker 建立 stellar-dummy 測試容器。這不等同目前 Pi Desktop 的 UPnP 自動設定與 Port Checker；不要額外手動啟動舊版測試容器，以免占用相同連接埠。若仍依舊版步驟測試，請先確認 App 與說明適用於你的版本，並依 Pi Desktop 畫面決定是否允許防火牆連線。外部網站測試結果也會受網路環境影響，應以目前 App 的診斷為準。

按 Win + R → 輸入 cmd → Enter。

2

輸入下面指令，找正在連線的 Ethernet／Wi-Fi 網卡，記下 IPv4 Address 與 Default Gateway；不要選 Docker／WSL 的 vEthernet 或 VPN 虛擬網卡。

3

在瀏覽器輸入 Gateway

例如你的 Default Gateway 是 192.168.213.1，就在網址列輸入：

http://192.168.213.1
4

登入路由器管理介面

輸入路由器管理帳號與密碼。帳密通常可在機身貼紙、ISP 文件、安裝資料或你自己設定的密碼管理工具中找到。

🔐 不要把路由器管理密碼、Wi‑Fi 密碼或公開 IP 貼到教學網站／截圖上。
5

尋找 Port Forwarding

不同品牌名稱可能不同，常見關鍵字：

Port Forwarding
Virtual Server
NAT Forwarding
NAT / Port Mapping
WHERE NEXT?

進入後台後，先不要亂改設定

你真正要找的是「NAT／Port Forwarding」。通常不需要修改 WAN、DHCP、PPPoE 或其他進階網路設定。

✓ 只有在 Pi Desktop 指示需要手動設定時，才繼續建立 Port Forwarding 規則。
💡 如果你的路由器由電信商提供，介面可能被整合在「Internet／網路／安全性／NAT」等頁面；名稱不同是正常的。
若找不到 Port Forwarding，先核對型號說明、管理權限與運作模式。AP／橋接模式通常要到上游路由器設定；有沒有此選單無法判斷是否使用 CGNAT。
WAN · 外部連入前先檢查

公網 IPv4、雙重 NAT 與 CGNAT

  1. 在路由器狀態頁找 WAN／Internet IPv4。這與電腦的 LAN IPv4 不同；在同一網路、未經 VPN／代理時，比較外部 IP 查詢服務顯示的 IPv4。
  2. WAN 若是 10.x.x.x、172.16.x.x～172.31.x.x、192.168.x.x，表示上游還有私有網路；若為 100.64.0.0～100.127.255.255，是共享位址範圍，常見於 CGNAT。位址不同是排查線索，仍需 ISP 確認。
  3. 若上游是你管理的另一台路由器，需讓外層轉發到內層 WAN，再由內層轉發到 Node 電腦；橋接／AP 模式則依設備與 ISP 指示調整。
  4. 若上游由 ISP 管理，詢問是否提供可接受入站連線的公網 IPv4。只設定家中 UPnP／Port Forwarding 無法穿過 ISP 的 CGNAT；動態公網 IPv4 也可能可用，不必將「固定 IP」視為唯一條件。

本節說明 IPv4 NAT；IPv6 需另確認應用程式與防火牆支援。依 路由器原廠排錯 ↗ 與 共享位址定義 ↗ 整理。UPnP 映射成功仍須再驗證外部可達性。

CHAPTER 07

常見排錯

先看現象，再判斷是 Port、Docker、同步或網路問題。

Pi Desktop 0.6.x 與 Mainnet 協定 v28 是同一個版本嗎？

不是。前者是桌面應用程式版本，後者是區塊鏈協定版本。本次查核時，官方 Node 頁 ↗ 正公告 Mainnet 升級至 v28；已運行 Mainnet 者需查看該頁連結的升級指南、期限與適用平台。不要因 App 已更新就假定容器／協定也已完成遷移，也不要將 Linux CLI 指令直接套在 Windows 教學上。

Port 顯示沒有開，是不是 Node 一定不能跑？

不一定。Port 狀態與節點對外連入能力有關；對外連線成功不等於其他節點能主動連入。依 App 流程啟動目前的 Port Checker／服務後再測試；沒有程式監聽時，就算轉發正確也會顯示關閉。確認 WAN、實際 LAN IP、UPnP／轉發與防火牆。若由外部工具輔助測試，須指定相同協定／埠號，並從家中網路以外測試；在同一 LAN 測公網 IP 會受路由器 NAT loopback 支援影響。

Node 容器沒有跑起來怎麼辦？

先執行 docker version：若沒有 Server，先排除 WSL／Docker 引擎問題。引擎正常時，在 Docker Desktop 的 Containers 查看該容器狀態與 Logs，確認映像下載、磁碟空間或埠號占用錯誤。記下 Pi Desktop、Docker、WSL 版本及錯誤時間，再向官方支援查詢。不要把刪除 volumes、重設 Docker 或清除區塊資料當成第一步，這可能需要重新同步。

一直顯示同步中，是壞掉了嗎？

初次同步或資料遷移可能耗時，沒有適用所有電腦的固定完成時間。記錄兩個時間點的 Local Block 與 Latest Block（須為同一網路），觀察差距是否縮小及 Outgoing Connections 是否存在。若完全不動，檢查容器 Logs、磁碟空間、網路與官方升級公告；Incoming 為 0 本身不足以判定同步故障。

下載 Node 時看到 Windows SmartScreen 警告怎麼辦？

先由 Pi Network 官方下載頁重新核對下載來源；若有數位簽章，檢查檔案內容中的發行者與簽章是否有效。SmartScreen 的信譽警告不等於惡意程式判定，但也不能只因教學說明就忽略。來源或檔案有疑慮時，先停止安裝並向官方確認，不要關閉整體防護。
